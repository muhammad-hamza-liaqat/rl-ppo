# Treasure Grid — RL + PPO demo

A tiny game plus an AI that teaches itself to play it with **PPO**, written from scratch in PyTorch.

```
. . . . . .
. A . X . .     A = agent   T = treasure (+1)   X = trap (-1)
. . . . X .     each step costs -0.01, max 50 steps
. X . . . .
. . . . . T
. . . . . .
```

## Setup (once)

```bash
cd ~/Desktop/rl-ppo-demo
python3 -m venv env
source env/bin/activate
pip install -r requirements.txt
```

## Run

```bash
python treasure_env.py     # sanity check: one random episode
python play.py --random    # watch an untrained (random) agent
python train.py            # train PPO (a few minutes on CPU), saves ppo_treasure.pt
python play.py             # watch the trained agent
```

## Live web UI (Next.js)

Watch the agent play, play the game yourself, and train it with live charts, all in the browser.
It needs two terminals.

**Terminal 1, the Python server** (runs the game and the PyTorch agent):

```bash
cd ~/Desktop/rl-ppo-demo
source env/bin/activate
uvicorn server:app --port 8000
```

**Terminal 2, the website** (one-time `pnpm install`, then `pnpm dev`):

```bash
cd ~/Desktop/rl-ppo-demo/web
pnpm install
pnpm dev
```

Open http://localhost:3000. The tabs:

| Tab | What happens |
|---|---|
| Watch the AI | The trained agent plays game after game. Arrows on the agent show its move probabilities. |
| Watch random moves | An untrained agent, for comparison. |
| Play yourself | Arrow keys or W A S D. The panel shows what the trained AI would do from your square. |
| Train | Trains PPO from scratch. After every update the agent plays one game on the board, and the charts update live. |

### Maze page (http://localhost:3000/maze)

A second demo with a different algorithm: **tabular Q-learning** on a maze. The agent keeps a table
with one row per square and one value per move. Squares turn gold as their value rises, and arrows show
each square's best-known move. The side panel shows every update with real numbers:

```
target = reward + γ × best value of next square
new Q  = old + α × (target − old)
```

Use **Start learning** to watch move by move, **Learn 50 episodes instantly** to skip ahead, and
**Walk the learned path** to follow the table from the start. You can change α, γ and ε while it runs.
Each browser tab gets its own maze, so refreshing the page starts a new one.

The difference from Treasure Grid: PPO learned a rule from 8 numbers that works on any random board.
Q-learning memorises this one maze; a new maze starts from an empty table.

### Palette taste page (http://localhost:3000/rlhf)

**RLHF in miniature**, the method used to fine-tune chat assistants, shrunk down to colour palettes:

1. **Pick** the palette you like more from pairs (arrow keys work). "Answer 20 for me" uses a pretend
   person with a known hidden taste, so you can check what the reward model recovers.
2. **Reward model**: a Bradley–Terry model, `P(A beats B) = sigmoid(r(A) − r(B))`, where `r` is a
   weighted sum of 8 readable traits (warmth, lightness, contrast, …). The page shows the learned weights.
3. **Tune with PPO**: the generator picks 5 colours one at a time and is rewarded by the reward model, with a
   **KL penalty β** that keeps it close to the original generator. Set β to 0 to see it collapse.

Look out for **reward hacking**: if the reward model learned a trait wrong, PPO exploits it. Making more
picks (which now come from the tuned generator) corrects the reward model, the same way real RLHF iterates.
`python rlhf.py` runs the whole loop in the terminal with the pretend person.

### Anomaly search page (http://localhost:3000/vision)

**RL for image processing** ("active vision"). Instead of looking at a whole image at once, the agent moves
and resizes a search box over a synthetic grayscale scan, step by step, until it says "found it".

- It sees two views, like an eye: a blurry 8×8 picture of the whole scan and a sharp 12×12 close-up of
  what is inside the box. The page shows both.
- Actions: up, down, left, right, bigger, smaller, found it.
- Reward: +0.1 when a move increases the overlap (IoU) with the anomaly, −0.1 otherwise; "found it" pays
  +1 + IoU if the overlap is at least 50%, otherwise −1.
- Training runs 16 scans side by side (`ppo_vec.py`), which is several times faster on a CPU.

The scans are generated by code (`vision_env.py`); this is a teaching demo, not a medical tool.

The browser talks to the server over a WebSocket at `ws://localhost:8000/ws`. To use another address, copy
`web/.env.example` to `web/.env.local` and change `NEXT_PUBLIC_WS_URL`.

## Reading the training log

- **avg reward / win / trap**: should climb from about −0.9 / ~5% wins to about +0.9 / ~95% wins.
- **entropy**: how random the policy is. It starts at ln(4) ≈ 1.39 and falls as the agent gets confident.
- **kl**: how much the policy changed in one update. PPO keeps this small (roughly < 0.02).

## Experiments to try

1. **Reward design**: set the step penalty to `0.0` in `treasure_env.py`. Does the agent dawdle?
2. **Harder game**: `TreasureGridEnv(size=8, n_traps=8)`. You will likely need more `--updates`.
3. **Remove the clip**: set `clip_eps=100` in `PPOConfig`. Training gets less stable.
4. **Blind the agent**: drop the 4 trap flags from the observation. It can't see traps, so it can't avoid them.
